# 官方 POS RAW 打印中继（Windows 7）

这个功能拦截的是官方 POS 发送到一个专用“中继打印队列”的 RAW/ESC-POS 数据，再由独立的本机中继守护进程识别、记录并发送到真实热敏打印机。外卖票据可重排，堂食/收款票据保持原始布局转发；它不会、也不能拦截已经直接发到物理打印机的打印任务。

## 文件位置说明

外卖业务设置保存在 `data/settings/takeout.json`。`data/takeout_proxy_status.json`、`data/takeout_proxy_control.json` 和 `data/takeout_jobs.json` 是守护进程运行状态、停止信号和订单流水，不是设置项，因此有意保留在 `data/` 根目录，不参与设置导入/拆分。

销售数据库固定在 `data/db/sales.db`；从旧版本启动时只会把 `data/sales.db`（以及 SQLite 的 `-wal/-shm` 伴随文件）移动到新目录，不会因配置迁移选项被删除。

中继守护进程与收银主界面是两个进程：首次启动成功后，关闭或崩溃本 POS 界面都不会关闭 `127.0.0.1:9101` 的监听。只有在“打印机中继”页面主动停止/清除配置，或 Windows 注销/关机时，守护进程才会停止。

## 首次配置

1. 在本 POS 的“系统设置 → 打印机设置”选择真实物理热敏打印机；不要选择下面要新建的中继队列。
2. 进入“系统设置 → 打印机中继”，填写一个未使用的队列名，例如 `YGF 外卖中继`，端口保持 `9101`，点击“启动独立服务”。状态显示“守护中继运行中”后，再点击“中继识别测试”。
3. 打开 Windows 7 的“设备和打印机”，添加本地打印机，选择“创建新端口 → Standard TCP/IP Port”。主机名填写 `127.0.0.1`；端口号填写 `9101`；协议选择 `RAW`。
4. 给这个新队列安装可原样输出 ESC/POS 的热敏打印驱动。一般可使用真实热敏打印机已安装的同款驱动，但这个队列的名称必须与物理打印机不同。
5. 如果只验证外卖重排，可先把“外卖订单/制作单”改为 `YGF 外卖中继`。如果要让官方 POS 的堂食/收款票据也参与营业额识别，则这些打印目标也必须指向同一个中继队列；堂食/收款票据会原样转发，并在订单号、金额和付款状态可靠时参与增强模式。
6. 回到本 POS 点击“检查 Windows 队列”。通过后，先打印一张真实外卖单和一张真实堂食/收款单，分别检查原始采样、金额和付款状态识别结果，再决定是否启用金额分流。

## 日常使用

- 中继启动后，只接受本机 `127.0.0.1` 的连接；不会开放给局域网。
- 可以退出本 POS 主界面；官方 POS 中继守护进程会继续工作。再次打开本 POS 的“外卖设置”页可查看它的状态和最新任务。
- “自动判断”策略下，只有官方 POS 订单号、最终金额和明确付款/结账证据都验证通过，才会进入增强模式；中继异常或识别失败会自动回到兼容模式。也可以在“打印机中继”页临时选择“强制兼容模式”，但不能手动强制增强。
- 收到非外卖内容或无法识别菜品的任务时，系统不会按外卖规则重排或分流；会尽量把原始小票转发到实体打印机，并标记为“状态未知/兼容模式”，避免因解析失败造成漏打。若要获取堂食营业额，必须让该票据经过中继，并在确认模板字段可靠后再启用对应识别逻辑。
- 同一平台订单号只会自动打印一次。需要补打时，使用“重打最近外卖单”；该操作会明确记为重打并累计联数。
- “制作联份数”和“存根联份数”至少保留一联；两者为 0 时系统会拒绝打印。

## 停用 / 删除

1. 先在官方 POS 将所有指向中继队列的打印目标改回原物理打印机或其它合法队列。
2. 在本 POS 的“打印机中继”页点击“临时停止服务”，需要永久停用时取消“启用中继监听”并保存。这一步不会删除 Windows 打印机，避免误删真实设备。
3. 确认官方 POS 已不再使用该队列后，才在“设备和打印机”中手工删除 `YGF 外卖中继` 队列和其 TCP/IP 端口。

## 排查

- “端口被占用”：换一个未占用端口，例如 `9102`，同时修改 Windows 队列端口；如果页面显示守护进程异常，先停止中继，等待状态变为“未启动”后再调整端口。
- “收到任务但没有菜品”：中继队列的驱动没有输出 RAW 文本；换用支持 ESC/POS RAW 的热敏驱动。
- “打印回环”：本 POS 的真实打印机误选成了中继队列。系统会阻止已填写队列名的同名输出；改回物理热敏打印机。
