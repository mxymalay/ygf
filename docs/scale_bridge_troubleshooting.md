# ScaleBridge 故障排查

## “未找到 com0com 安装程序”

确认完整部署目录包含 `ThirdParty\com0com\Setup_com0com...W7_x64_signed.exe`，不要只复制主 POS EXE。

## “未找到 setupc.exe”

安装窗口可能被取消，或系统要求重启。完成重启后再次点击“初始化 / 修复”。不要在日常启动脚本中运行 `setupc install`。

## “COMx 已被真实设备占用”

程序不会覆盖真实设备。称重端口冲突请到“POS 称桥接”修改后重新初始化；支付端口冲突请到“收钱吧插件”修改后重新创建支付配对。

## “端口已属于现有配对，但配置未指定对端”

点击“检查虚拟端口配对”读取实际对端。核对该配对确实用于本系统后保存，再执行初始化；程序不会自动接管来源不明的配对。

## 物理秤端口能打开但没有重量

确认型号为 DIBAL ACS-G315，并检查：`9600 / 8N1 / DTR 开 / RTS 关 / 无流控`。测试按钮发送的查询应为单字节 `24`，合法回包应以 `0D` 结束。

开发机没有真实电子秤时，不要使用不存在的 COM 端口反复点击“测试物理秤”。先完成步骤 2 的虚拟 COM 配置，再在步骤 3 使用“开发测试：模拟秤并启动服务”。它会启动真实 ScaleBridge 服务并验证两路固定 `0.500 kg` 模拟回包，但不替代真实秤验收。

## 物理端口被占用

停止 ScaleBridge 服务后再做物理秤直测。正常营业时只有服务可以打开物理端口，官方 POS 和本 POS 必须使用各自虚拟端口。

## 服务启动后不断重连

生成诊断报告，重点检查：

- `PhysicalScalePort` 是否存在；
- 保存的设备身份是否和当前设备一致；
- `OfficialBridgePort`、`PrivateBridgePort` 是否仍属于正确配对；
- `last_error` 是否提示端口占用；
- Windows 服务日志 `%ProgramData%\YgfPos\logs\scale_bridge_service.log`。

## 支付配对测试失败

到“收钱吧插件”页面，测试前关闭正在占用发送端和插件接收端的软件。先执行“检查支付配对”，再执行“双向测试支付配对”。支付操作不会修改 POS 称桥接。

## 官方或私有秤通道测试失败

确认 ScaleBridge 服务状态为 `RUNNING`，并关闭占用待测 POS 虚拟端口的软件。先通过“测试物理秤”和“检查两组端口配对”，再测试通道；本 POS 通道会在官方端最后一次查询超过默认 1000 ms 后恢复主动查询。

## 删除被拒绝

如果配对名称或序号与所有权清单不一致，程序会拒绝删除。保留 `data\scale_bridge_installation.json` 和诊断报告，由技术人员核对，不能模糊删除所有 com0com 设备。
